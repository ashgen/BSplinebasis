## 2024-05-24 - `constexpr` mathematical utilities
**Learning:** Marking pure mathematical utility functions (e.g., factorials, binomial coefficients) and array helpers (e.g. `make_array`, `evaluateInterval`) as `constexpr` in a C++ codebase allows the compiler to perform constant folding at compile-time when parameters are known, significantly reducing runtime overhead. However, `std::array::fill` and `std::array` reverse iterators are not `constexpr` in C++17, so manual loops are necessary.
**Action:** When refactoring functions returning arrays to be `constexpr` in C++17, use aggregate initialization (`std::array<T, N> arr{};`) and standard `for` loops rather than `fill` or reverse iterators. Include `<cstddef>` and `<algorithm>` to avoid missing header issues in stricter evaluation contexts.

## 2024-05-24 - `std::array` initialization overhead
**Learning:** In C++, replacing a manual uninitialized array filling loop (`std::array<T, N> ret; for...`) with aggregate zero-initialization (`std::array<T, N> ret{};`) is safe and conceptually cleaner, but introduces unnecessary overhead if all elements will be assigned later or if the unassigned elements were zeroed correctly by the original explicit loop anyway (e.g. `changearraysize`). The zero-initialization step iterates over the entire array, which is inefficient if only part of it is immediately overwritten and the rest was explicitly meant to be zeroed via loop. Default initialization leaves memory uninitialized with zero overhead.
**Action:** When optimizing array value-initialization by switching to uninitialized local arrays, verify that all elements will be assigned a value. Do not apply this optimization if only a subset of elements is overwritten (e.g., when copying from a smaller array where `ordera < order`), as explicit zero-initialization is strictly required for the unassigned elements to prevent undefined behavior. For arrays of plain old data (POD) types that will be immediately and entirely overwritten (e.g., within a subsequent loop), use default initialization (`std::array<T, N> arr;`) instead of value initialization (`std::array<T, N> arr{};`).
