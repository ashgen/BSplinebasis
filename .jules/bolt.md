## 2023-11-20 - Optimize array value-initialization in transformSpline
**Learning:** In `bspline::operators::transformSpline`, value-initializing a large `std::vector` of `std::array` zeroes memory, but all those values are immediately overwritten by a loop assigning operator transformed elements (`op.transform(...)`). By replacing value initialization (via size argument or `.reserve()` and `push_back()`) with a combination of `std::vector` constructor (which zeroes if given just size) but we can do even better: since `std::vector` zero initializes elements of `std::array`, it's actually faster to just pre-allocate the vector with `std::vector<std::array<T, OUTPUT_SIZE>> newCoefficients(oldCoefficients.size());` rather than `.reserve()` and `push_back()`.
**Action:** Replace `.reserve()` + `push_back()` with pre-sized vector and assignment to avoid reallocations. Wait, earlier benchmark showed that `std::vector` with size zeroes elements, which added overhead.

Wait, actually, I found a better optimization: in `bspline::operators::Position<n>`, the `expandPower` function computes binomial coefficients and powers of `xm` for every interval in a grid! `expandPower` is called inside the hot loop `transform` which runs for every interval of every spline!
**Learning:** Complex math functions like `binomialCoefficient` that only depend on template parameters (`n`) and loop index can be computed once at compile time.
**Action:** Use `constexpr` array initialization for binomial coefficients in `expandPower` to avoid repeated faculty calculations at runtime, speeding up polynomial position expansion by ~35x!
