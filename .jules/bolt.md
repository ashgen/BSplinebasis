## 2024-06-23 - Performance Bottleneck in Hot Loops with Validity Checks
**Learning:** Found an interesting performance bug: extensive runtime validity checks inside a core mathematical class (`Spline.h`, `Support.h`, `Grid.h`) take an astronomical amount of execution time when running inner loops (e.g. `Spline<...>::operator()` and `linearCombination`). The `DURING_TEST_CHECK_VALIDITY()` macro was being evaluated in production build because `BSPLINE_ADD_TEST_CHECKS` was hardcoded in `examples/CMakeLists.txt` and `tests/CMakeLists.txt`. We should make it a configurable CMake option or remove it from production builds.
**Action:** Remove `BSPLINE_ADD_TEST_CHECKS` from the main compile definitions in `examples/CMakeLists.txt` since examples are production-like binaries simulating user usage. It can stay in tests but shouldn't be defined for examples.
